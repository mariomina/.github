# .github de mariomina

Valores por defecto de GitHub para los repos de `mariomina` que no tienen los suyos ([docs](https://docs.github.com/en/communities/setting-up-your-project-for-healthy-contributions/creating-a-default-community-health-file)). Es público porque GitHub lo exige.

| Ruta | Qué hereda cada repo |
|---|---|
| `.github/ISSUE_TEMPLATE/` | 4 formularios: Épica, Tarea, Bug, Mejora |
| `CONTRIBUTING.md` · `SECURITY.md` | Forma de contribuir y aviso de seguridad |
| `acciones/pr/` | Acción compuesta con los checks de PR en un solo job (mariomina/mario-home#134): título convencional, `AGENTS.md` (filtro global, modo repo) y CI de Python con uv. Se llama como paso: `uses: mariomina/.github/acciones/pr@v1`. GitHub redondea cada job a 1 min, así que un job con pasos gasta menos cuota que 3 jobs |
| `.github/workflows/` | Workflows reutilizables (`ci-python`, `pr-titulo`, `release-please`): no se heredan, se llaman con `uses: mariomina/.github/.github/workflows/<archivo>@v1`. `ci-python`, `pr-titulo` y `agents-md` quedan hasta que ningún repo los llame; los repos nuevos usan `acciones/pr` |
| `.github/workflows/proyectos.yml` + `scripts/proyectos_sync.py` | Automatizaciones de los Projects de la cuenta y de la org cada 15 min (el workflow se mantiene vivo solo frente a los 60 días sin actividad; su log solo tiene cuentas): alta de los issues de los repos enlazados, primer Status al entrar, último al cerrar, archivado a los 14 días. Secreto `PROJECTS_TOKEN` (`gh secret set PROJECTS_TOKEN -R mariomina/.github --body "$(gh auth token)"`; repetir si se renueva el token de `gh`) |
| `.github/workflows/agents-md.yml` + `scripts/filtro_global.py` | Filtro global (mariomina/mario-2-cerebro#276): el `AGENTS.md` de cada repo existe, declara `tipo-repo` y no exceptúa reglas globales. En local y en el CI de `mario-home` revisa además los duplicados frente a `mario-home/AGENTS.md` y, con `--nombres`, que los documentos base no nombren un repo ni un check que no existe (#55) |
| Versiones | release-please + `release.yml`: cada versión mueve el tag `v<major>`. Los repos llaman a los reutilizables con `@v1`. **Decisión:** `v1` es mutable a propósito, como recomienda GitHub para el tag mayor de una acción ([releasing and maintaining actions](https://docs.github.com/en/actions/how-tos/create-and-publish-actions/release-and-maintain-actions)): un cambio llega a todos los repos sin una PR en cada uno. Se acepta porque quien publica y quien llama son el mismo dueño y el tag solo lo mueve `release.yml` tras fusionar en `main`; las acciones de terceros, en cambio, van por SHA. El reutilizable `release-please` crea la PR de versión con el token de la GitHub App (secreto `APP_PRIVATE_KEY`, que le pasa el repo que lo llama), espera su CI y la fusiona solo en verde (`github_pendientes.py --fusionar-version`); ese merge dispara la publicación (mariomina/.github#28, mariomina/mario-2-cerebro#280) |
| `scripts/github_pendientes.py` | Barrido de pendientes de GitHub sobre los repos de los punteros de `mario-home/AGENTS.md`, en cascada (mariomina/mario-2-cerebro#280). Lo programa `mario-home` (`mantenimiento.yml`, cada 3 h), que es privado: el log del barrido nombra repos, PR, ramas y títulos, y aquí sería público (si corre en un repo público, solo imprime cuentas). Fusiona las PR de versión atascadas con CI en verde. Dependabot espera el veredicto de un verificador y el permiso de Mario, como una PR de trabajo (pstack, mariomina/mario-home#134); workflows desactivados, CI rojo en la rama principal (primero), ramas y PR de más de 24 h, repos con más de 3 ramas activas (DORA, mariomina/mario-home#361) e issues sin proyecto solo se avisan. En local: `python3 -I scripts/github_pendientes.py` (tabla) o `--linea` (la línea `GitHub:` de la apertura de sesión de Claudian y Hermes, desde la caché `~/.cache/mariomina-github/pendientes.json`) |

Un repo que tenga su propia carpeta `.github/ISSUE_TEMPLATE/` deja de heredar los formularios. Los repos nuevos nacen de [`mario-plantilla-repo`](https://github.com/mariomina/mario-plantilla-repo).
